# Audio Deepfake Detection with a 1D CNN

Is a voice recording real, or generated by AI?
This project trains a binary classifier that scores each utterance as bona fide or deepfake.
Performance is measured by Equal Error Rate (EER) on a course leaderboard.

*Individual project, Introduction to Deep Learning, Institute for Natural Language Processing (IMS), University of Stuttgart, winter semester 2025/26.*

---

## Task and data

- **Input:** pre-extracted acoustic features per utterance, shape `[180, 321]`. That is 180 feature dimensions (LFCC + delta + delta-delta) over 321 time frames.
- **Labels:** `1` = bona fide (real speech), `0` = deepfake.
- **Splits:** train, dev (2,000 utterances), a public leaderboard test set (500) and a final test set (1,000) without labels.
- **Metric:** EER, the point where the false acceptance rate equals the false rejection rate. Lower is better. 50% means random guessing.

The dataset was provided by the course and is available on [Zenodo](https://zenodo.org/records/18342979). It is not included here.

## Approach

**Model: a 1D CNN over time** (`model.py`)

```
[B, 180, 321]  features as channels, time as sequence
   │
   ├─ Conv1d(180→64, k=5) + BatchNorm + ReLU + MaxPool   → [B, 64, 160]
   ├─ Conv1d(64→128, k=3) + BatchNorm + ReLU + MaxPool   → [B, 128, 80]
   ├─ Conv1d(128→256, k=3) + BatchNorm + ReLU + MaxPool  → [B, 256, 40]
   │
   ├─ Global average pooling over time                    → [B, 256]   utterance embedding
   └─ Linear 256→128 + ReLU + Dropout(0.3) + Linear 128→1 → [B]        one logit per utterance
```

The 180 feature dimensions are treated as input channels, so the convolutions slide along time.
Global average pooling turns a variable-length sequence into one fixed-size embedding.

**Training** (`train.py`)

- **Loss:** `BCEWithLogitsLoss`. The model outputs raw logits, which is numerically more stable than applying a sigmoid first.
- **Optimizer:** Adam, learning rate 1e-3, weight decay 5e-4, batch size 8.
- **Augmentation:** SpecAugment-style masking. Up to two time masks (≤ 30 frames) and two feature masks (≤ 18 dimensions) per batch, applied with probability 0.9. The goal is robustness to deepfake methods the model has not seen in training.
- **Learning-rate schedule:** the learning rate is halved when dev EER stops improving for 5 epochs.
- **Early stopping:** training stops after 10 epochs without a better dev EER. The best checkpoint by dev EER is kept.

**Baseline.** I also implemented a bidirectional LSTM (`RNNAudioModel`). It performed worse than the CNN, so the CNN was used for the final submission.

**Data checks** (`audit.py`). Before training, the script checks every split for duplicate IDs, features without labels, overlap between train, dev and test, and label imbalance.

## Experiments

All settings are command-line arguments, so runs differ only in their flags.

| Run | Batch size | Weight decay | Best epoch | Dev EER |
|---|---|---|---|---|
| First run (15 epochs) | 16 | 1e-5 | 12 | 0.10% |
| With augmentation | 16 | 1e-4 | 10 | 0.10% |
| With augmentation | 16 | 1e-3 | 8 | 0.10% |
| With augmentation | 16 | 5e-4 | 15 | 0.10% |
| With augmentation, dropout 0.4 | 16 | 5e-4 | 8 | 0.10% |
| With augmentation | 32 | 5e-4 | 10 | 0.10% |
| **With augmentation (final)** | **8** | **5e-4** | **22** | **0.00%** |

**What this shows.** Every configuration reached a dev EER of about 0.1%, which means only one or two misclassified utterances out of 2,000.
The dev set was almost solved, so dev EER could not reliably separate the configurations.
That is a limitation of the evaluation setup, not proof that the model is perfect.
The real test is speech the model has not seen, which is what the final evaluation measured.

## Final evaluation: in-domain and out-of-domain

The final test set had two parts:

- **In-domain:** the same kinds of real and fake speech as in training.
- **Out-of-domain (OOD):** an unseen attacker and new bona fide speakers.

The final score was a weighted EER: 0.9 × in-domain + 0.1 × OOD. There were 59 valid submissions.

| Test set | EER | Rank | Mean score | Score std |
|---|---|---|---|---|
| Public leaderboard (test1), first-run model | 0.41% | | | |
| Final model, in-domain | 0.00% | 1 (tied with 16 others) | -0.79 | 11.32 |
| Final model, out-of-domain | 25.00% | 12 (tied) | -9.33 | 7.54 |
| **Final model, weighted** | **2.50%** | **7 of 59 (tied)** | | |

Scores are logits. Higher means more likely bona fide.

**Takeaways**

- **In-domain detection was solved, generalization was not.** The model made no errors on familiar data. On the OOD set, it got 1 in 4 decisions wrong at the EER threshold.
- **The OOD set decided the ranking.** 17 submissions tied at 0.00% in-domain, so differences came almost entirely from OOD. The best OOD result in the class was 18.75%, so every model struggled there.
- **The model shifted toward "fake" on new data.** The mean score dropped from -0.79 to -9.33. New real speakers were likely pushed toward the fake side, so one fixed threshold cannot serve both domains.
- **Masking was not enough.** Time and feature masking teach the model to cope with missing information. They do not simulate a new way of generating speech. This matches the general view that generalization to unseen attackers is the core problem in deepfake detection.
- **Small OOD set.** OOD EERs moved in steps of about 2.1 points, which suggests roughly 48 utterances per class. A gap of one or two ranks is only a few utterances, so small differences should not be over-read.

## How to run

Download the dataset from Zenodo and unzip it into `data/` (`data/train`, `data/dev`, `data/test1`). Training runs on a CPU.

```bash
pip install -r requirements.txt

# Check the data
python audit.py

# Train (final configuration)
python train.py \
    --train_features data/train/features.pkl --train_labels data/train/labels.pkl \
    --dev_features data/dev/features.pkl --dev_labels data/dev/labels.pkl \
    --model conv --batch_size 8 --weight_decay 5e-4 --epochs 30

# Predict with the included checkpoint
python predict.py --test_features data/test1/features.pkl \
    --checkpoint checkpoints/best_model.pt --output prediction.pkl

# Evaluate predictions against labels
python evaluate.py prediction.pkl data/dev/labels.pkl
```

## What I would do next

- **Build a harder validation set.** Hold out entire deepfake methods and speaker groups from training. A validation set like that would have predicted the OOD drop, while the dev set here could not.
- **Compare with pretrained speech models.** Self-supervised models such as wav2vec 2.0 are a strong baseline for spoofing detection.
- **Calibrate scores per domain.** The score shift on OOD data suggests that threshold calibration could recover part of the loss.
